# Личный агент поиска вакансий

Приложение ищет Python-вакансии на нескольких площадках, проверяет условия правилами, готовит карточку: оценка соответствия, сопроводительное письмо и советы по резюме. Отклики агент не отправляет — откликаетесь вы сами (решение 05.11.2026). Подходящие вакансии приходят в Telegram уведомлением с кнопкой «Посмотреть вакансию и письмо». Запуск и остановка — на компьютере; при выключении или сне компьютера обработка останавливается.

## Первый запуск

Зависимости уже установлены в этой папке. Токены и ключи задаются в файле **.env** в корне проекта: скопируйте `.env.example` в `.env` и заполните значения. Для входа и запуска откройте **scripts/setup.command** двойным щелчком; после настройки **scripts/start.command** сразу запускает поиск, без меню и команд в Telegram.

1. В Telegram откройте [официального BotFather](https://t.me/BotFather), отправьте `/newbot`, задайте имя и свободное имя пользователя бота. Полученный токен запишите в `.env` как `TELEGRAM_BOT_TOKEN`. Присылать токен в чат Codex не нужно.
2. В `.env` заполните `TELEGRAM_OWNER_ID` — числовой ID вашего личного чата (он же получатель уведомлений). Узнать его можно автоматически: `.venv/bin/python -m job_finder pair` покажет одноразовую команду `/start <код>` — отправьте её своему боту, и программа сама запишет ID. Альтернатива — узнать свой ID у @userinfobot и вписать вручную.
3. Там же укажите модели: `LLM_BASE_URL` (для OpenAI — `https://api.openai.com/v1`), `LLM_API_KEY`, `LLM_MODEL` (для карточек достаточно `gpt-4o-mini`) и `LLM_EMBEDDING_MODEL` (эмбеддинги дедупликации, по умолчанию `text-embedding-3-small`). Без ключа доступны поиск и письма из подтверждённых фактов резюме, оценка будет «недоступна».
4. В меню **scripts/setup.command** выберите «Войти в HH (API, без браузера)». Укажите email или телефон HH и пароль — либо войдите по одноразовому коду из SMS/письма. При необходимости капча показывается картинкой в окне программы. Токен хранится локально в `.state/tokens/hh.json` и обновляется автоматически. Браузер не используется.
5. Откройте **scripts/start.command** или выберите «Запустить агента» в меню настройки. Поиск запускается командой `/search` в Telegram (или `search` в терминале). Подходящие вакансии придут уведомлением с кнопкой; отклики агент не отправляет. `/status` покажет состояние и количества, `/letter ID` — конкретное письмо.

Перед запуском полезно проверить площадки и ключи: `.venv/bin/python -m job_finder doctor`.

Чтобы остановить поиск и обработку, нажмите **Ctrl+C в окне скрипта**. Для продолжения запустите скрипт снова. Не запускайте для одного бота другую программу с polling/webhook. Один экземпляр агента защищён локальной блокировкой.

## Команды Telegram

| Команда | Действие |
| --- | --- |
| `/search` | Запустить раунд поиска по всем источникам (параллельно) |
| `/status` | Состояние скрипта, источников и результат последнего раунда |
| `/browse` | Категории вакансий со счётчиками |
| `/browse <категория>` | Первая полная карточка категории: `ready`, `clarification`, `rejected`, `delivered`, `read`, `found`, `error`, `closed`, `skipped` |
| `/next` | Следующая карточка в последней категории (та же кнопка есть под карточкой) |
| `/clarifications` | Первые 20 вакансий на уточнение: название, причина и ссылка |
| `/clarifications 2` | Следующая страница списка уточнений; номер нужной страницы указан в ответе |
| `/history` | Последние 20 результатов |
| `/letter 123456` | Точное письмо, дополнения и подготовка |
| `/keep ID` | Одобрить уточнение — карточка готовится и придёт уведомлением |
| `/skip ID` | Пропустить вакансию и весь её кластер |
| `/unskip ID` | Отменить пропуск кластера — вакансии вернутся на переоценку |
| `/help` | Краткая справка |

ID — `source:native_id` (например, `hh:123456` или `telegram:pythonrabota:321`). Уведомления о новых вакансиях по умолчанию **отключены** (`DELIVER=false`, тихий режим): поиск запускается `/search`, просмотр — `/browse` и `/next`, по одной карточке с кнопкой «Следующая вакансия». Старые команды `/pause`, `/resume`, `/reconcile`, `/requeue`, `/queue` и `/settings` больше не управляют работой и подсказывают актуальные.

## Правила

- Python обязателен в названии/описании/требованиях. Несовпадение технологий не блокирует; решение принимается по каждому активному профилю (`PROFILES` в `.env`), вакансия проходит, если проходит хотя бы один.
- **Профиль ru**: удалёнка («только РФ» подходит, ограничение чужой территорией — отказ) или офис/гибрид в Москве («Московская область»/«Подмосковье» не считаются); релокация только с целевым городом; командировки — отказ; порог 150 000 ₽/мес применяется только к зарплатам в RUB (годовая нормализуется к месячной); без зарплаты/в другой валюте нужен явный Middle+ или Python-стек.
- **Профиль intl**: удалёнка worldwide или офис/релокация в Дубай; зарплатного порога нет (валюта как есть); явный Junior/Trainee — отказ всегда.
- Неоднозначная зарплата, грейд или география уходят на уточнение. Автоматического курса валют нет.
- Видимое предложение пройти тест больше не отклоняет вакансию: она готовится как обычно, а в карточке появляется метка «Тест: потребуется пройти при отклике». Общая реклама тестов и скрытые блоки не влияют.
- Модель выбирает подходящие факты и до двух ограниченных утверждений о практическом знакомстве с технологиями из списка. Добавленные утверждения и подготовка показываются только владельцу. Карьерные факты не выдумываются и исходный профиль не меняется. Первая версия формирует письма на русском или английском из проверяемых фраз.

## Восстановление и границы версии

Отклики автоматически не отправляются: решение 05.11.2026 — агент ищет и готовит вакансии, откликается пользователь сам. Активный код отправки (браузер, `apply`/`reconcile`/`claim`/`finish`/`recover`, таблица `attempts`) удалён вместе с Playwright. Миграция базы выполнена (06.11.2026): старые отклики перенесены в архив `application_history`, перед миграцией автоматически делался бэкап.

Капча, истёкший вход и неожиданная структура API останавливают затронутую работу. Остановите скрипт, при необходимости войдите через **scripts/setup.command** (`api-login`), затем снова запустите **scripts/start.command**. Не применяются обход капчи, скрытые методы HH или экспорт чужих браузерных сессий.

Поиск идёт через адаптеры (`job_finder/adapters/`, список в `SOURCES`): hh.ru (программный API мобильного приложения), RemoteOK (публичный API), Habr Career и We Work Remotely (RSS), Telegram-каналы (`TG_CHANNELS`, Telethon, только чтение). Поиск запускается командой `/search` в Telegram или `python -m job_finder search`; источники опрашиваются параллельно, сбой одного источника не останавливает остальные (повтор по таймеру). Для hh выдача при ограничении дополнительно разбивается по четырём диапазонам опыта. RSS-ленты и первый обход канала честно помечаются как неполные. Автоматических интервалов нет — пользователь сам решает, когда искать. Telegram-каналы требуют доступ к Telegram (при необходимости — VPN/прокси).

По умолчанию новые вакансии автоматически не рассылаются (тихий режим, `DELIVER=false`): счётчики — в `/status`, просмотр — `/browse`/`/next` по одной полной карточке (описание вакансии, причина отбора, ссылки кластера, оценка с причиной, письмо, советы по резюме, подготовка) с кнопкой «Следующая вакансия». При `DELIVER=true` каждая подходящая вакансия приходит уведомлением «Нашлась новая релевантная вакансия» с кнопкой, по нажатию бот присылает карточку. Уточнения приходят отдельным сообщением с подсказками `/keep`/`skip`; решения — `/keep` и `/skip`, `/unskip` отменяет пропуск кластера. Пауза — это пауза доставки уведомлений; поиск и подготовка при этом продолжаются. Пока скрипт выключен, бот не отвечает.

Вакансия, где работодатель предлагает тест, больше не отклоняется: она готовится как обычно, а в карточке появляется метка «Тест: потребуется пройти при отклике».

Чтение входящих сообщений работодателей и изменение их статусов в этой версии ещё не подключены. Сбой Telegram не останавливает поиск и подготовку: ответы на команды остаются в очереди до восстановления связи. Редкий сбой после доставки может продублировать часть уведомления.

После длительного простоя Telegram может поменять последовательность ID обновлений. Если после недели бездействия бот перестал принимать команды, остановите приложение и повторите привязку через `pair`.

## Запуск из терминала

```sh
cd /Users/vll/VLL/projects/job_finder_v2
.venv/bin/python -m job_finder init
.venv/bin/python -m job_finder configure
.venv/bin/python -m job_finder pair
.venv/bin/python -m job_finder api-login
.venv/bin/python -m job_finder doctor
.venv/bin/python -m job_finder run
```

Установка в новую папку на macOS/Linux с Python 3.12 или новее:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m pip install -e . --no-deps
.venv/bin/python -m unittest discover -s tests
```

Секреты находятся в `.env`, сессия и база — в `.state/`; обе папки исключены из Git. Не публикуйте их и не удаляйте базу. Обновляя приложение, сохраняйте `.state/agent.sqlite3` вместе с файлами `-wal`/`-shm` либо делайте копию после остановки процесса.
