# Разведка веб-площадок второй волны (06.11.2026)

Задача: `job_finder_v2-285`. Цель — решить, можно ли написать HTTP-адаптеры
(без браузера) для hirify.me, vseti.app, remocate.app, ancor.ru/vacancy.

## Протокол проверки

Все запросы — `curl -sL` с браузерным User-Agent, таймаут 15–30 с,
проверка `robots.txt`, структуры списка вакансий, полей карточки,
пагинации и признаков антибота. Сайты, отдавшие TLS-ошибку, дополнительно
проверены через web_fetch (другая инфраструктура).

### ancor.ru/vacancy — ДОСТУПНО, адаптер реализуем

| Аспект | Наблюдение |
| --- | --- |
| Платформа | 1С-Битрикс, серверный рендер (676 КБ HTML на /vacancy/) |
| Список | `<article class="b-card">` на /vacancy/ (12 карточек на странице) и каталогах по отраслям, в т.ч. `/vacancy/catalog/informatsionnye-tekhnologii/` (3 карточки) |
| Поля карточки | заголовок + ссылка `/vacancy/job/<id>/` + **полное описание в HTML-экранированном атрибуте `data-text`** (обязанности/требования) |
| Детальная страница | JSON-LD `JobPosting`: `identifier.value` = id, `datePosted` (ISO), `jobLocation.address.addressLocality` (город), `baseSalary` (валюта/период/значение — в примере пустое), `employmentType` |
| Пагинация | `/vacancy/?page=N` (до 19), на каталоге ИТ пагинации нет |
| robots.txt | `Disallow: /*?` — URL с query-параметрами запрещены; `/vacancy/` и каталоги разрешены |
| ToS | В проверенных страницах (agreement-vacancy) явного запрета автоматизированного сбора не найдено — это согласие на обработку ПД, не анти-скрейп |
| Защита | Captcha/Cloudflare не обнаружены; обычный HTTP-клиент работает |

**Решение по ancor:** адаптер реализуем чтением публичных HTML-страниц —
`/vacancy/` + `/vacancy/catalog/informatsionnye-tekhnologii/` **без
query-параметров** (уважение robots.txt: только первые страницы, охват
помечается `incomplete`). Листинг даёт title/url/описание; дата, город
и зарплата — из JSON-LD детальной страницы при fetch.

**Дополнение по итогам живой проверки (вечер 06.11.2026):** первые два
GET отдали 12 карточек (`maxPage: 19`) — это был устаревший
composite-кэш Битрикса. Свежие ответы (включая проверку через внешнюю
инфраструктуру web_fetch) показывают **«Найдено 0 вакансий»** — список
вакансий на сайте сейчас реально пуст. Детальные страницы (JSON-LD
JobPosting) по-прежнему работают по прямым URL. Адаптер корректно
обрабатывает пустой листинг (0 hits, честная пометка неполноты);
живой прогон успешен, выдача пуста из-за состояния сайта, а не бага.

## Гипотеза о причине блокировки

Все три недоступных сайта живут на российских IP (81.177.x, 81.19.x,
176.124.x) и обрывают именно TLS-рукопожатие — типично для гео-фильтров
или DDoS-защит, блокирующих зарубежные подсети. Telegram (t.me) при этом
открывается напрямую. Стоит проверить из браузера с этой машины: если
сайты открываются в браузере — блокируется именно не-браузерный клиент
или нужен прокси; если нет — нужен VPN/другая сеть.
