# 01. Обзор проекта

## Что это за проект

**job-finder** (пакет `job-finder`) — личный агент одного пользователя для сайта [hh.ru](https://hh.ru). Программа:

1. ищет вакансии по ключевому слову **Python** (удалённая работа);
2. читает каждую вакансию через браузер и применяет утверждённые правила отбора (зарплата, грейд, формат, тесты);
3. готовит персональное сопроводительное письмо — языковой моделью или детерминированным шаблоном;
4. ведёт долговременную очередь откликов в локальной SQLite;
5. отправляет отклики на hh.ru через **обычный интерфейс сайта** в отдельном браузерном профиле (Playwright + Chromium);
6. сообщает о результатах в Telegram.

Приложение запускается и останавливается **только на компьютере пользователя**; Telegram используется исключительно для просмотра отчётов, без кнопок и управляющих команд.

## Зачем проект существует

Официальный API hh.ru с 15 декабря 2025 года прекратил поддержку приложений для соискателей: в контракте нет метода отправки отклика (`POST /negotiations`, `apply-to-vacancy`, `/resumes/mine` отсутствуют). Подробности — в [ресёрче](../research/2026-10-19-connectivity.md). Поэтому единственный легальный автоматизированный путь — работа через публичный интерфейс сайта в браузере с собственным логином пользователя. Первый реальный отклик таким способом был выполнен и подтверждён 21 октября 2026 года (вакансия `137924141`, см. [отчёт](../research/2026-10-21-first-application.md)).

Проект строго личный: одна учётная запись, одно согласованное резюме, явный режим «просмотр без отправки» по умолчанию.

## Ключевые принципы (инварианты)

- **Отклик считается отправленным только после подтверждения площадки** (надпись «Вы откликнулись» на странице вакансии). Отсутствие надписи не считается доказательством неудачи.
- **Никаких слепых повторных отправок**: после начала отправки (нажатия кнопки) результат при сбое становится `unknown` и блокирует дальнейшие отправки до ручной проверки.
- **Защита от дублей**: намерение отправить фиксируется в БД *до* нажатия кнопки (`claim`), каждая вакансия обрабатывается один раз, повторное обнаружение при поиске не дублирует запись.
- **Единственное согласованное резюме** `b424f687ff113123eb0039ed1f7a496e413267`; выбор проверяется по ID radio-поля, а не по названию.
- **Тесты пропускаются**: видимое предложение пройти тест для конкретной вакансии → пропуск навсегда, без попыток обхода.
- **Письма не выдумывают карьерные факты**: только фразы из подтверждённого профиля + до двух ограниченных утверждений о практическом знакомстве с технологиями из закрытого списка.
- **Секреты и сессия локализованы**: `.env` (0600), `.state/` (0700), база (0600); ошибки санитизируются, токены и cookies никуда не попадают.
- **Только публичная навигация по сайту**: никаких приватных эндпоинтов HH, обхода капчи или экспорта чужих сессий.

## Ограничения текущей версии (осознанные)

- Чтение входящих сообщений работодателей и смена их статусов **не подключены**.
- Автоматического курса валют нет: вакансии в не-RUB валюте уходят на уточнение.
- Анкеты с неизвестными ответами требуют участия пользователя (никогда не заполняются наугад).
- Письма собираются только из проверяемых фраз (русский/английский); свободная генерация отключена.
- Работа только пока компьютер включён: это не сервис, а локальный процесс.
- Автономная отправка этим приложением на живом аккаунте ещё не прогонялась целиком: нужны ключи, вход в HH и включение `HH_LIVE` пользователем.
