# 05. Бизнес-правила отбора вакансий

Источник правил — [одобренный дизайн](../superpowers/specs/2026-10-19-hh-agent-design.md); реализация — [`hh_agent/rules.py`](../../hh_agent/rules.py) (функция `evaluate`) и проверки тестов в [`hh_agent/browser.py`](../../hh_agent/browser.py) (`has_test`).

## Порядок проверки `evaluate(vacancy)`

1. **Закрыта** → `closed` («Вакансия закрыта»).
2. **Тест** (`vacancy.test_required`) → `rejected` («Пропущена: предложено пройти тест»).
3. **Python** обязан упоминаться в названии/описании/требованиях (слово целиком: `\bpython\b` или «питон*»). Совпадение в названии компании или постороннем тексте сайта не считается. Нет → `rejected`.
4. **Удалёнка**: `remote=False` → `rejected`; `remote=None` (не подтверждено на странице) → `needs_clarification`.
5. **Командировки**: фразы «без командировок»/«no travel» вычитаются из текста; оставшееся упоминание командировок/travel → `rejected`.
6. **География удалённой работы**: шаблоны «только/обязательно … проживание/нахождение/Москва/РФ», «удалённо из …/within/from …» → `needs_clarification`.
7. **Грейд** — вычисляется по контекстам «ищем/вакансия/уровень/позиция/грейд…»; фразы про наставника («под руководством», «с наставником») отсекаются от контекста грейда.
8. **Зарплата** — решающая таблица ниже.

## Грейд и зарплата

Порог: **150 000 ₽ в месяц** (до налогов или на руки — без пересчёта налогов).

| Ситуация | Решение |
| --- | --- |
| Вилка, верхняя граница ≥ 150 000 | `ready` — «Вилка допускает 150 000 ₽» |
| Фиксированные/«от» ≥ 150 000 | `ready` |
| Максимум < 150 000 | `rejected` |
| Зарплата не указана | `ready` только при явном Middle+; одних лет опыта («от 3 лет») недостаточно |
| «От X» без верхней границы, X < 150 000 | `ready` при Middle+, иначе `needs_clarification` |
| Валюта ≠ RUB или период ≠ месяц | `needs_clarification` (курсов валют нет) |
| Вилка не разобрана (0, перевёрнутая, неоднозначная) | `needs_clarification` |
| Junior/Trainee/стажёр без зарплаты | `rejected`/`needs_clarification` (не проходит уровень) |
| Junior/Middle смешанный | подходит, только если работодатель явно рассматривает Middle |

Нюансы грейда:

- `middle|mid|senior|lead|principal|staff|мидл|сеньор|ведущий|старший|руководитель|тимлид|техлид` — признаки Middle+.
- Senior-наставник **не** повышает грейд Junior-вакансии.
- При подтверждённой подходящей зарплате грейд не ограничен (даже Junior с вилкой ≥ 150 000 проходит).

## Правило пропуска тестов (жёсткое)

- Видимое на странице вакансии или на любом новом шаге формы предложение **пройти тест для этой вакансии** → `rejected` с причиной «Пропущена: предложено пройти тест». Тест не открывается, отклик не отправляется, обход не ищется.
- Проверка выполняется: перед любым действием, способным отправить отклик, и после появления нового шага формы (до и после заполнения письма, до клика).
- НЕ блокируют: скрытые элементы, общая реклама тестов навыков, баннеры вне контекста вакансии (детектор проверяет локальные блоки и близкий контекст: «ваканси|отклик|работодател»).
- Уже отправленный отклик **важнее** позднее появившегося баннера теста: сначала сверяется фактический статус.
- Пропуск сохраняется отдельным событием (`skip_events`) и попадает в дневную сводку; повторный поиск не возвращает вакансию в очередь автоматически.

## Анкеты работодателей

- Неизвестные ответы (право на работу, проживание, зарплатные ожидания и т.п.) **никогда не выдумываются**: наличие любого видимого дополнительного поля формы → `needs_clarification` («В анкете есть дополнительные вопросы работодателя»).
- Общий текст «Для отклика необходимо ответить на несколько вопросов работодателя» сам по себе не является тестом и не блокирует, если вопросы не показаны.
- Видимость резюме: блокирует только фактически отображаемое предупреждение `[data-qa="hidden-resume-warning"]`; скрытое (max-height: 0) — не блокирует. Настройки резюме приложение не меняет.

## Сопроводительные письма — правила

- Язык письма — язык вакансии (≥8 кириллических букв → русский, иначе английский); язык письма не является подтверждением знания языка.
- Письмо собирается только из: (1) фраз-фактов [profile.json](../../hh_agent/profile.json) (1–6 штук, `python_backend` первой), (2) до 2 «ограниченных утверждений» о практическом знакомстве с технологией из закрытого списка `PRACTICE_TECHNOLOGIES` (Kubernetes, Kafka, RabbitMQ, Airflow, ClickHouse, Terraform, Ansible, Pytest, Pandas, NumPy, MLflow, gRPC, Elasticsearch, Prometheus, Grafana, Selenium, SQLAlchemy, Pydantic), только если технология упомянута в вакансии.
- Каждое добавленное утверждение обязано сопровождаться точной записью плана подготовки; утверждения и подготовка видны только владельцу в Telegram и не отправляются работодателю.
- Выдумывать должности, даты, образование, сертификаты, размер команды, достижения — запрещено; модель получает только факты профиля и данные вакансии (ненадёжный текст), ответ дословно сверяется с локальной сборкой.
- Без ключа модели письмо собирается детерминированно (`python_backend` + до 5 фактов по тегам), без добавленных утверждений.

## Другие ограничения охвата

- Направление — Python в задачах/требованиях (backend, автоматизация, тестирование, данные, инфраструктура — любые с Python).
- Несовпадение технологий, отрасли и обязанностей НЕ блокирует отклик (приоритет — широкий охват).
- Только hh.ru; LinkedIn вне объёма первой версии.
