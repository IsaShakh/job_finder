# 09. Тесты

Запуск полного набора:

```sh
.venv/bin/python -m unittest discover -s tests
```

**156 тестов** (после перевода на API HH; на момент отчёта о проверке 21.10 было 80). Браузерные тесты требуют установленного локального Chromium (`PLAYWRIGHT_BROWSERS_PATH=.cache/ms-playwright`).

## Что тесты принципиально НЕ доказывают

- Фикстуры браузерных тестов — подставные страницы: селекторы сверены с живым HH при ресёрче, но живой сайт может меняться (для этого и существуют `AttentionRequired`-остановки).
- Тесты API-клиента работают на MockTransport: структура страницы входа сверена с живым hh.ru (30.10.2026), но сами вызовы API на живом аккаунте требуют входа пользователя.
- Реальная доставка Telegram и совместимость с конкретной моделью требуют подключения пользователя.
- Полный автономный цикл на живом аккаунте (поиск → письмо → отправка → подтверждение) ещё не прогонялся приложением: нужны ключи, вход и `HH_LIVE=true`. Ранее подтверждён только ручной контрольный отклик.

## Полезные приёмы из тестов

- Браузерные тесты подменяют все ответы через `context.route("**/*")` и считают клики через `page.expose_function`.
- Telegram/модель тестируются подменённым `http_client` (httpx-транспорт), без сети.
- База тестов — временная SQLite в `tempfile`.
