# 04. Модель данных

База: `.state/agent.sqlite3`, SQLite, WAL-режим, права 0600. Версия схемы — `PRAGMA user_version = 3`. При запуске выполняется миграция (добавление колонки `kind` в `outbox`). База созданной более новой версией приложения отклоняется (`ValueError`).

## Таблица jobs — очередь вакансий

| Колонка | Тип | Назначение |
| --- | --- | --- |
| `id` | TEXT PK | ID вакансии hh.ru (числовая строка) |
| `data` | TEXT | JSON-снимок `Vacancy` (исходное содержимое без изменений) |
| `status` | TEXT | один из `STATES` (ниже) |
| `reason` | TEXT | объяснение последнего решения на русском |
| `letter` | TEXT | JSON `Letter` (null, пока не готово) |
| `resume_id` | TEXT | ID резюме, зафиксированное при `claim` |
| `evidence` | TEXT | подтверждение отклика с URL страницы |
| `created`, `updated` | TEXT | ISO-метки UTC |

### Статусы (STATES)

| Статус | Значение | Терминальный? |
| --- | --- | --- |
| `found` | найдена поиском, ждёт чтения и оценки | — |
| `rejected` | отсеяна правилами (зарплата, тест, формат…) | да |
| `needs_clarification` | нужна проверка человеком (неясная вилка, география, анкета) | да* |
| `ready` | письмо готово, стоит в очереди на отправку | — |
| `sending` | отправка начата (claim выполнен, кнопка ещё не подтверждена) | — |
| `sent` | отклик подтверждён площадкой | да |
| `unknown` | результат отправки неизвестен; только ручная проверка | да* |
| `error` | сбой при подготовке/отправке без начатой отправки | да* |
| `closed` | вакансия закрыта/в архиве/удалена | да |

\* `decide()` не может перезаписать `sent`/`sending`/`unknown`; повторная оценка возможна только после вмешательства человека (например, ручное обновление статуса).

Контрольная запись: вакансия `137924141` (Инженер поддержки и развития (LLM-агенты), At Prof) вставлена как `sent` при создании БД — это ранее подтверждённый вручную отклик, исключается из сводок «с предыдущей сводки».

## Таблица attempts — журнал попыток отправки

| Колонка | Назначение |
| --- | --- |
| `id` | автоинкремент |
| `job_id` | ссылка на `jobs` |
| `started`, `ended` | время попытки |
| `status` | `sending` → `sent`/`unknown`/… при завершении |
| `evidence` | подтверждение (для `sent`) |

Создаётся в момент `claim`, закрывается в `finish`/`recover`. Одна активная попытка (`sending`) на строку.

## Таблица settings — ключ-значение (JSON-значения)

| Ключ | Назначение |
| --- | --- |
| `paused` | глобальная пауза отправок (по умолчанию `true`) |
| `browser_blocked` | блокировка работы с HH (капча/вход/структура); сбрасывается только локальным запуском |
| `attention_reason` | текст причины блокировки для `/status` |
| `last_search` | Unix-время последнего поиска |
| `search_report` | JSON отчёта последнего поиска `{ids, pages, incomplete, notes}` |
| `next_send_at` | Unix-время, после которого можно отправлять следующий отклик |
| `telegram_offset` | следующий update_id для getUpdates |
| `telegram_next_poll` / `telegram_next_delivery` / `telegram_next_cleanup` | троттлинг/ретраи Telegram |
| `telegram_chunk_<id>` | прогресс доставки чанков сообщения `<id>` из outbox |
| `digest_day` | дата последней дневной сводки |
| `last_digest_at` | ISO-метка последней сводки |
| `search_requested`, `reconcile_requested` | устаревшие флаги (сбрасываются при старте; Telegram больше не управляет) |

## Таблица inbox — дедупликация Telegram-обновлений

`update_id` (PK), `command` (что сделано с обновлением), `created`. Гарантирует, что повторно доставленное обновление не вызовет повторного ответа; `telegram_offset` продвигается только вместе с записью.

## Таблица outbox — исходящие уведомления

| Колонка | Назначение |
| --- | --- |
| `id` | автоинкремент |
| `text` | текст сообщения |
| `sent` | 0/1 — доставлено |
| `created` | время |
| `kind` | `event` (справочное, не отправляется автоматически), `reply` (ответ на команду), `success` (подтверждённый отклик) |

Автоматически доставляются только `reply` и `success`. Миграция v2→v3: старые сообщения с префиксом «Отклик подтверждён: » получили `kind='success'`.

## Таблица skip_events — пропуски из-за тестов

`job_id`, `reason`, `created`, `reported` (0/1). Пропуск теста пишется отдельным событием и включается в ближайшую дневную сводку; после включения — `reported=1`. Это гарантирует, что пропуски между сводками не теряются.

## Файлы состояния

- `.state/agent.sqlite3` (+ `-wal`/`-shm`) — база; при переносе копировать все три файла (после остановки процесса).
- `.state/agent.lock` — файл fcntl-блокировки.
- `.state/browser-profile/` — постоянный профиль Chromium (сессия входа в HH), права 0700.
- `.state/backups/` — резервные копии БД (например, перед миграцией).
- `.state/control-response-*.png` — контрольные снимки страниц.

Всё состояние в `.gitignore`, не публикуется.
