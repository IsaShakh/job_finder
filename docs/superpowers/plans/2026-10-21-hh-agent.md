# HH agent implementation plan

**Goal:** Build a local, owner-only Telegram agent that discovers Python jobs, applies the approved salary/grade rules, prepares letters and sends through a dedicated hh.ru browser session with durable duplicate protection.
**Architecture:** One asynchronous Python process, SQLite journal/outbox, deterministic Playwright adapter, a configurable LLM client, Telegram long polling. Local credentials and browser profile; preview until explicitly enabled. No service deployment or autonomous mass run as part of development.
**Tech Stack:** Python 3.9+, Playwright, httpx, python-dotenv; unittest and local browser fixtures.
**Spec:** docs/superpowers/specs/2026-10-19-hh-agent-design.md

## Global Constraints
- Only the exact approved resume ID. Never retry an ambiguous send. Persist intent immediately before submit and recover sending as unknown on restart.
- Visible vacancy-related tests skip permanently; generic ads and hidden warnings do not. Existing application wins over a later test banner.
- No broad click on an application button before entering the full response form. One submit; confirm then stop.
- Owner + private chat restriction, durable Telegram update dedupe, no secrets in output, model receives only profile facts and vacancy data.
- Current folder was an empty non-Git project with prior research. Initialize a local feature branch here; no extra worktree is needed. Preserve research.
- Missing live credentials do not block local implementation/testing. Live readiness and offline verification are reported separately.
- User already approved this design and implementation. No repeat plan approval.

## Review Focus
Check concurrency at pause/submit, crash after click before confirmation, duplicate commands and two local processes, hidden/clipped test banners, incorrect resume selection, false salary/grade matches, changed/closed vacancies, leakage of tokens in errors, job text prompt injection, model claims separated from profile facts, and uncertainty in browser selectors. Check what fixtures cannot establish about the live site. Telegram failure must never turn a successful HH send into a retry.
